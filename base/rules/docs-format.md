# 문서 형식 규칙 (모든 저장소)

`~/.claude/rules/`에 놓이는 모듈 규칙. 저장소 `CLAUDE.md`·`docs/`에 다른 규칙이 있으면 그쪽이 우선한다.

- `.md`는 처음부터 markdownlint를 통과하게 쓴다: 헤딩·목록 앞뒤 빈 줄, 표 구분선 정렬, 연속 빈 줄 금지. 줄 길이(MD013)는 한국어 산문이라 무시한다.
- 파일마다 역할이 하나다. README는 입구(무엇인지·설치·링크). 새 주제는 `docs/<주제>.md`를 만들고 README에는 링크 한 줄. README가 120줄, `CLAUDE.md`가 200줄을 넘기면 줄이지 말고 분리한다.
- 파일·폴더 경로와 항목 ID(`P-NN`, `C-NN` 등)는 클릭되는 링크로 쓴다. 코드 블록 안에는 링크가 안 되므로 구조 목록은 표로.
- 변경 이력은 Keep a Changelog(`[Unreleased]` 누적, 영문 헤더 Added/Changed/Fixed). 릴리즈 노트는 한국어 음슴체.
- 파일·함수·설정을 삭제하거나 이름을 바꾸면 그 이름을 `**/*.md`에서 grep해 참조도 같은 커밋에서 고친다.
- 날짜가 의미 있는 파일은 `YYYY-MM-DD-` 접두사, 하루에 파일 하나. 시점 의존 표현("지금은", "최근")은 날짜로 바꿔 쓴다.
- `.md` 파일·GitHub Issue·PR 본문·GitHub Release 노트 가리지 않고, 목록 항목에서 주어(파일명·기능명 등)와 설명을 `—`나 `:`로 한 줄에 이어쓰지 않는다. 길이와 무관하게 주어를 본문 줄로, 설명은 그 아래 들여쓴 하위 bullet으로 줄바꿈한다. 표 안에서는 하위 bullet 대신 `<br>`로 줄바꿈한다.
  - 예외: "필드명: 값"을 나열하는 구조화된 기록(예: 조사 이슈의 질문/결론/조사일/출처/영향)은 한 줄에 그대로 둔다 — 서술문을 이어붙인 게 아니라 필드 나열이라 대상이 아니다.
