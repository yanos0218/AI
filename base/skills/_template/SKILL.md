# skill-name

한 줄 요약 — 이 스킬이 대신해 주는 반복 작업이 무엇인지.

## 0. 시작 전 확인

- 저장소에 이미 같은 절차를 정한 문서(`docs/*.md`, 저장소 `CLAUDE.md`)가 있으면 그쪽이 우선한다
  - 무엇을 찾아볼지 여기 나열.
- 확인한 결과를 사용자에게 한 줄로 알리고 진행한다.

## 1. 절차

여러 단계면 체크리스트로 쓰고 "답변에 복사해 진행 상황을 표시하라"고 지시한다.

```text
작업명
- [ ] 1. 첫 단계 — 실제로 실행할 명령이나 열어볼 파일
- [ ] 2. 둘째 단계
- [ ] 3. ★ 사용자 확인 ★ — push, 배포, 삭제 등 되돌리기 어려운 지점
- [ ] 4. 결과 보고 — 실행한 명령과 출력
```

## 2. 세부 자료는 references/로

- SKILL.md는 A4 한 장(50~60줄)을 넘기지 않는다.
- 긴 표, 예외 케이스, 명령어 모음, 형식 예시는 `references/<주제>.md`로 빼고, 여기엔 **"어떤 상황에서 그 파일을 읽어야 하는지"**만 적는다. 참조는 SKILL.md에서 한 단계만(참조 파일이 또 다른 파일을 가리키지 않게).

## 하지 않는 것

- 이 스킬이 절대 하지 않는 행동을 나열한다. 이유는 한 줄로
  - 날짜·저장소 이름 같은 시점 의존 정보는 넣지 않는다.

## 작성 시 원칙 (이 절은 실제 스킬에서는 삭제)

- **description이 발동 기준이다.** 무엇을 하는지만 쓰면 안 뜬다
  - 사용자가 실제로 쓰는 말투("~해줘", "~하자")를 따옴표로 넣고, 3인칭으로 쓴다.
- **저장소별 내용은 참조만 한다.** 다른 저장소의 규칙·사례를 여기 복사하지 않고, "저장소 문서가 있으면 그쪽 우선"으로 가리킨다.
- **시점 의존 정보 금지.** 날짜, 특정 버전 번호, "지금은 ~" 같은 표현은 곧 틀린 정보가 된다.
- **선택지를 늘어놓지 않는다.** 기본값 하나 + 예외 조건 하나.
- **다 만들면 3가지 상황으로 시험한다.** 새 세션에서 서로 다른 조건(문서 있음 / 없음 / 예외 케이스)으로 발동·동작을 확인한 뒤 완료로 본다.
- 저장소별 스킬은 그 저장소 `.claude/skills/`에, 저장소를 가리지 않는 스킬만 이 저장소(claude-config)에 둔다.
