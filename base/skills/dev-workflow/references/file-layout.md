# 표준 폴더 구조, 이름 규칙, 정리 절차

SKILL.md §1-B를 보충한다. 저장소 `CONTRIBUTING.md`·`CLAUDE.md`에 구조 규칙이 있으면 그쪽이 우선한다.

## 1. 기본 구조 (모든 저장소)

| 경로 | 무엇 | 없으면 |
| --- | --- | --- |
| `README.md` | 입구. 무엇인지·설치·실행 요약과 링크. 120줄 안팎 | 만든다 |
| `CLAUDE.md` | Claude가 지킬 저장소 규칙. 200줄 이하 | 저장소 표준 체크리스트(claude-config `docs/repo-standard.md`)대로 제안 |
| `CHANGELOG.md` | 변경 이력 (Keep a Changelog) | 제안 |
| `docs/` | 상세 문서. 주제당 파일 하나. 진행 보드(`PROGRESS.md`), 테스트(`testing.md`), 배포 등 | 주제가 둘 이상 생기면 만든다 |
| `tests/` | 테스트 코드·페이지 | 테스트가 생길 때 |
| `scripts/` | **배포·운영에 쓰이는** 스크립트 | 필요할 때 |
| `tools/` | **개발 중에만** 쓰는 도구(검사·패키징) | `scripts/`와 구분이 필요해질 때 |
| `.github/workflows/` | CI | 저장소 표준대로 |
| 소스 폴더 | 스택 관례: 정적 사이트 `deploy/`·`public/`·`src/`, Java `src/main`, Python 패키지명 | 스택 관례 유지 |

`scripts/`와 `tools/`의 구분 기준: **배포되는가.** 배포·운영 서버에서 실행되면 `scripts/`, 개발자 PC나 CI에서만 실행되면 `tools/`.

## 2. 이름 규칙

- 파일·폴더 이름은 소문자 kebab-case (`place-collector.py`, `nas-deployment.md`). 스택이 다른 관례를 강제하면(Java 클래스 등) 그쪽.
- 날짜가 의미 있는 파일은 `YYYY-MM-DD-` 접두사(관찰 기록, 로그, 회의록).
- 항목 ID가 있는 문서는 ID를 파일명으로 (`P-105.md`, `C-13.md`).
- 임시·실험 파일은 저장소에 두지 않는다. 스크래치패드나 `drafts/`.
- 파일 이름을 바꾸면 그 이름을 `**/*.md`와 스크립트에서 grep해 같은 커밋에서 고친다.

## 3. 정리 절차

1. `git ls-files`로 전체 목록 → 폴더별 개수와 용도를 표로.
2. 후보 찾기: 어디서도 참조되지 않는 파일(`grep -rl <이름>`이 비는 것), 이름이 `tmp`·`old`·`copy`·`backup`인 것, 같은 내용이 두 곳에 있는 것.
3. **제안표**: 파일 | 현재 | 제안(이동 경로 / 삭제 / 유지) | 이유. 사용자 확인을 받는다.
4. 이동은 `git mv`(이력 보존). 삭제는 항목마다 확인. 한 커밋에 이동과 참조 수정을 같이 넣는다.
5. README 구조 절과 `CLAUDE.md`를 새 구조에 맞게 갱신한다.

## 4. 판단이 갈릴 때

- **docs/에 넣을지 README에 넣을지** → README가 100줄을 넘기면 docs/로. README에는 링크 한 줄.
- **한 파일이 두 폴더에 걸칠 때**(예: 배포도 하고 개발도 쓰는 스크립트) → 배포 쪽(`scripts/`)에 두고 tools/에서 호출.
- **사용자가 "그냥 정리해줘"라고 할 때** → 제안표까지만 만들고 멈춘다. 이동·삭제는 확인 후.
