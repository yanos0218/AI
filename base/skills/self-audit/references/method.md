# self-audit 방법

## 1. 감사 표시 파일

- 위치: 이 세션 트랜스크립트 파일(`transcript_path`, `SessionStart` 훅과 같은 필드) 의 폴더 안 `.self-audit-marker`. 스킬 실행 중엔 지금 세션 자체 정보에서 같은 값을 구할 수 있다. 못 구하면 `~/.claude/projects/`에서 지금 저장소 경로가 들어간 폴더명을 찾는다.
- 내용: 한 줄, 그 폴더 안 `*.jsonl` 개수(정수).
- 이 경로는 항상 지금 작업 디렉터리(저장소) 밖이라, 쓸 때마다 사용자 승인이 뜬다(정상 — Claude Code가 작업 디렉터리 밖 쓰기를 항상 확인받는 기본 동작. 발동 시험 2026-09-13에서 실제로 확인됨). 승인하면 그대로 진행한다.
- `base/hooks/session-start-check.sh`가 이 파일과 지금 개수를 비교해 15개 이상 쌓이면 알려준다.

## 2. 서브에이전트 지시문

`Agent` 도구로 Sonnet 모델 general-purpose 서브에이전트에게 아래를 그대로 전달한다(대화 원문을 본 세션에 쌓지 않기 위함 — `~/.claude/CLAUDE.md` "파일을 많이 읽어야 하는 조사·감사는 서브에이전트에 맡기고 요약만 받는다"):

> 이 저장소의 세션 트랜스크립트 폴더 `<폴더 경로>`에서 표시 파일 이후 생성된 `*.jsonl` 전부(표시 파일이 없으면 최신 30개까지만)를 읽어라. 각 파일에서 `type:"user"`·`type:"assistant"` 메시지의 텍스트 블록만 보고, `tool_result`·`tool_use`의 원문 인자·출력은 건너뛴다(용량이 커서 스킵 — 세션 하나가 6MB를 넘긴 사례가 있음). 개별 파일이 10MB를 넘으면 그 파일은 건너뛰고 건너뛴 파일명만 보고에 적어라.
>
> 아래 문서를 대조 기준으로 삼아라: `<저장소 CLAUDE.md·docs·전역 CLAUDE.md·rules/ 경로 목록>`. 이미 문서에 있는 내용은 후보에서 뺀다.
>
> 찾을 것 세 가지, 각각 근거(대략 언제·무슨 말이었는지 한 줄)와 함께:
>
> 1. 사용자가 같은 지적을 두 번 이상 한 것
> 2. 문서에 적힌 규칙인데 실제로는 어겨진 사례
> 3. 채팅에서 결정됐지만 어떤 문서에도 안 적힌 것
>
> 결과는 표(항목·근거·문서 반영 후보 문구)로만 반환하고, 대화 원문을 그대로 인용하지 마라(항목당 한 줄 이내).

## 3. Issue 작성 형식

- 라벨: `task` + `auto-detected`(이 스킬이 자동으로 찾아낸 것과 사람이 발견한 것을 구분).
- `auto-detected` 라벨이 없으면 먼저 `gh label create auto-detected --description "self-audit 스킬이 자동으로 찾아낸 후보" --color FBCA04`로 만든다.
- 제목: `self-audit YYYY-MM-DD: <한 줄 요약>`.
- 본문: 서브에이전트가 준 근거 한 줄 + "Issue로만" 선택한 이유(있으면).

## 4. 상한

- 세션 30개, 파일당 10MB — 이 이상은 다음 감사로 미룬다(끝없이 다 읽지 않는다).
- 표시 파일이 없는 첫 실행은 최신 30개까지만 본다(전체 이력을 한 번에 훑지 않는다).
