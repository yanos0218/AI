## 추천 진행 순서 (2026-09-09)

**Script — 보안 처리 → 최소 표준 + shellcheck CI** (운영 서버 스크립트라 검사 가치가 있음)

1. 사용자: Root CA를 재발급할지 결정. 이 CA로 서명한 서버 인증서가 살아 있으면 재발급은 서버 인증서 재배포를 뜻하므로 사용자만 판단 가능. 재발급하지 않기로 해도 2번은 한다.
2. Claude(확인 후): zip에서 `.key`·`.srl`을 빼고 `.crt`만 남기거나 zip을 통째로 제거 → `.gitignore`에 `*.key *.pem *.p12 *.srl .env*` → `git filter-repo`로 이력에서 키 제거 → **force push**(되돌리기 어려움, 확인 항목). 이력 정리를 원치 않으면 트리에서만 제거.
3. Claude(확인 후): `CLAUDE.md`(세션 시작 시 README, 검사 명령, 확인 기준), `CHANGELOG.md`(날짜 절), `.github/workflows/lint.yml`(markdownlint + shellcheck, main만, timeout), Issues 규칙 한 줄. `repo-setup` 스킬로 실행하면 시나리오 2로 기록.
4. push는 확인 후. 첫 CI 실행 결과 확인.

**Etc — 최소 3파일** (`CHANGELOG.md`, `CLAUDE.md`, `.gitignore`). HTML 분석 도구라 CI 가치가 낮고 재사용 가능성은 있어 보관보다 최소 유지. 원치 않으면 GitHub Archive.

둘 다 다른 저장소에 push하는 일이라 항목마다 확인을 받는다.
