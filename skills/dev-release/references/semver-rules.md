# SemVer 세부 판단 기준

## 기본 형식

`MAJOR.MINOR.PATCH` (예: 1.4.2)

## 등급 판단 상세

### MAJOR (breaking change)

- 공개 API의 함수/파라미터 제거, 시그니처 변경
- CLI 명령/옵션 제거 또는 의미 변경
- 설정 파일 포맷 변경으로 기존 설정이 깨짐
- 기본 동작(default behavior) 변경으로 기존 사용자가 다른 결과를 얻게 됨
- 커밋 메시지에 `BREAKING CHANGE:` 또는 `!` (예: `feat!:`)가 있으면 우선 근거로 삼는다

### MINOR (기능 추가, 하위 호환)

- 새로운 옵션/플래그/명령 추가 (기본값이 기존 동작을 보존)
- 기존 함수에 옵션 파라미터 추가
- Deprecation 경고 추가 (아직 제거는 아님)
- 커밋 메시지 `feat:` 가 있으면 최소 MINOR

### PATCH (호환되는 수정)

- 버그 수정
- 문서, 주석, 테스트만 변경
- 내부 구현 리팩터링 (외부 동작 동일)
- 의존성 패치 업데이트
- 커밋 메시지 `fix:`, `docs:`, `refactor:`, `test:`, `chore:` 등

## 여러 변경이 섞여 있을 때

한 릴리즈에 `feat:`와 `fix:`가 섞여 있으면 MINOR. `feat!:` 하나라도 있으면 전체가 MAJOR.
등급을 낮추기 위해 breaking change를 누락하지 않는다 — 사용자가 놓치면 실제 장애로 이어질 수 있다.

## pre-1.0 (0.y.z) 특수 취급

0.y.z 버전대는 아직 안정화 전이라는 신호이므로, 팀/프로젝트 관례가 없다면 다음을 기본으로 삼되 사용자에게 확인한다.

- breaking change → MINOR (y를 올림)
- 기능 추가/수정 → PATCH (z를 올림)

관례가 이미 있다면(과거 태그 이력에서 유추 가능) 그 관례를 따른다.

## 근거를 못 찾을 때

커밋 메시지가 Conventional Commits를 따르지 않으면, `git diff <last-tag>..HEAD --stat`와 실제 변경 내용을 보고 위 기준에 맞춰 직접 분류한 뒤, 분류 근거를 사용자에게 제시하고 확인받는다.
