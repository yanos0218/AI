# 릴리즈 노트 형식

저장소에 노트 형식 문서나 기존 노트 파일(`.github/release-notes/*.md`, 과거 GitHub Release)이 있으면 **그 형식을 그대로 따른다**. 아래는 아무것도 없을 때의 기본값이다.

`CHANGELOG.md`(개발자용, Keep a Changelog 영문 헤더)와는 **별개 문서**로, 사람이 읽기 좋게 정리한 한국어 요약이다. 노트 파일을 요구하는 워크플로면 태그 push 전에 커밋해 두고, 아니면 `gh release create --notes-file`에 넘긴다.

## 기본 형식

```markdown
# vX.Y.Z - 한국어 제목

## 추가
- 새 기능/화면

## 변경
- 기존 동작이 달라진 부분

## 수정
- 버그 수정

## 제거
- 제거된 기능(있을 때만)

## 보안
- 보안 관련 변경(있을 때만)

## 메모
- 그 외 참고사항, 등급 결정 이유
```

## 규칙

- Release 제목은 `vX.Y.Z - 한국어 제목`. 제목은 이 버전을 한 줄로 요약.
- 섹션은 **필요한 것만**, 순서는 **추가 → 변경 → 수정 → 제거 → 보안 → 메모**.
- **음슴체/명사형**으로 통일: "~함 / ~됨 / ~추가 / ~제거". "~했습니다 / ~해요" 같은 문장형 종결은 쓰지 않는다 — 읽는 사람이 사실상 작성자 본인이라 건조한 톤이 다른 문서와 맞고 길이도 짧아진다.
- 고유명사·명령어·파일명·함수명·태그명은 원문 그대로.
- 세부 구현 설명은 커밋 로그와 문서에 맡기고, **버전 차이를 빠르게 인지할 내용만** 남긴다.
- 백로그 ID(`P-NN` 등)를 쓰는 저장소는 항목 끝에 괄호로 붙인다.
- 등급 결정 이유(예: "신규 기능 포함이라 MINOR")는 `## 메모`에 한 줄.

## 예시

```markdown
# v1.4.0 - 검색 필터 + 내보내기

## 추가
- 목록 화면 검색 필터(이름/태그)
- CSV 내보내기 버튼

## 수정
- 날짜 열이 잘리던 문제

## 메모
- 신규 기능 포함이라 MINOR
```
