# dev-workflow 스킬 — 초안 전 요구사항 메모 (C-13)

아직 SKILL.md를 쓰지 않았다. "개발용 스킬(파일 관리, 테스트 방법 정의)"은 발동 문구와 산출물이 정해져야 초안이 가능하다. 아래 세 가지를 사용자와 정한 뒤 `base/skills/_template`을 복사해 시작한다.

## 정해야 할 것

1. **발동 문구** — 사용자가 실제로 하는 말. 후보: "테스트 어떻게 해?", "테스트 방법 정리해줘", "이 저장소 테스트 규칙 만들어줘", "파일 정리해줘", "구조 잡아줘".
2. **산출물** — (a) 저장소에 `docs/testing.md`를 만들어 주는 스킬인지, (b) 매번 테스트를 실행·보고하는 절차 스킬인지, (c) 둘 다인지. kolo_pwa `docs/testing.md`는 (a)의 결과물이고 스택별(정적 사이트·Java·Python·셸)로 형태가 다르다.
3. **"파일 관리"의 뜻** — 폴더 구조 표준(예: `docs/`, `scripts/`, `tests/` 위치)인지, 정리(안 쓰는 파일 찾기)인지, 이름 규칙인지.

## 참고 원본 (복사 금지, 참조만)

- kolo_pwa `docs/testing.md` — 브라우저 테스트·관리자 콘솔 테스트·CI 잡 구성·순수 함수 테스트 규칙
- kolo_pwa `CONTRIBUTING.md` — PR 체크리스트
- 이 저장소 `docs/repo-standard.md` — 저장소 최소선(테스트 CI 항목)

## 시험 시나리오 (초안이 나오면)

| 상황 | 기대 |
| --- | --- |
| `docs/testing.md`가 이미 있는 저장소 | 그 문서를 우선하고 새로 만들지 않음 |
| 테스트가 하나도 없는 정적 HTML 저장소 | 스택에 맞는 최소 검사(`node --check`, 브라우저 테스트 틀)를 제안하고 사용자 확인 후 생성 |
| 배포만 요청한 경우 | 이 스킬이 아니라 저장소 배포 스킬로 넘김 |
