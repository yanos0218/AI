On 2026-08-04, kolo-api's `PlaceService.VALID_DISTRICTS` was expanded from the original 4 curated neighborhoods (myeongdong/hongdae/seongsu/ikseondong) to also accept all 234 nationwide 시/군/구, using romanized slugs like `seoul-gangnam-gu`/`busan-haeundae-gu` generated by `scripts/place-collector/generate_district_catalog.py`. This followed directly from [[feedback_collector_scope_vs_insertability]] — the user pushed back twice more on that same principle: first questioning why the collector's region UI needed curated-vs-nationwide checkboxes at all, then explicitly choosing "expand kolo-api's district model" (the fundamental fix) over a narrower "auto-relabel overlapping results" option when asked.

**What changed, concretely**:
- `district-catalog.json` (in `scripts/place-collector/`, committed — not gitignored like `area-catalog.json`) is now the single source of truth for nationwide district slugs/labels, shared by three places: kolo-api's `src/main/resources/nationwide-districts.json` (loaded into `VALID_DISTRICTS` at class-init), kolo_pwa's `strings.json` `districtLabel` (238 entries), and place-collector's own `lib/regions.py`/`lib/validate.py`.
- No kolo-api DB migration was needed — `Place.district` was already a free-text `VARCHAR(32) NOT NULL` with no FK/CHECK constraint, only a Java-level whitelist.
- `lib/romanize.py` implements Korea's Revised Romanization algorithmically (jamo decomposition + standard tables + ㄱ/ㄷ/ㅂ/ㄴ/ㄹ assimilation rules) — verified against ~30 well-known official district names before trusting it for all 234.
- kolo_pwa's consumer-facing district chip row (home screen) is deliberately still scoped to just the 4 curated neighborhoods (`CURATED_DISTRICTS` in `app.js`) even though the label map and backend whitelist now cover all 238 — accepting a district *value* and having real curated *content* (reviews/scores) for it are different things. Admin console's province/district `<select>`s are now linked (province change repopulates district options) — previously independent, which risked silently corrupting a nationwide place's district on save.

**How to apply**: If kolo curates a new neighborhood (a 5th, 6th, ...), add it to kolo-api's `CURATED_DISTRICTS` constant, kolo_pwa's `CURATED_DISTRICTS` array, and the district-catalog generation's OVERRIDES if needed — the nationwide catalog itself shouldn't need touching. If Korea's administrative boundaries ever change, re-run `generate_district_catalog.py` (reads `lib/area_catalog.py`'s TourAPI-sourced cache) and re-copy the output into kolo-api/kolo_pwa.
