# 관찰 2026-09-09 — claude-config 세션(이어짐)

## 요청 방식

- 보드를 열어 두고 "§2 진행하자, §3에서 할 수 있는 것 확인하고 진행하자"처럼 **문서의 절을 단위로** 지시한다. 항목 번호(C-NN)로 대화하는 것이 자리 잡음.
- 규칙·정의를 먼저 준다(산출물/결과물, 파일/폴더 정의). 용어를 정의해 주면 그대로 스킬 본문에 넣기를 기대.
- "버전 정의에 따라 진행되는 게 맞을까?"처럼 **내가 만든 규칙을 내가 지키는지**를 확인한다. 규칙 이탈에 민감.

## 원하는 것

- 조사는 최신·검증·기록. 반복 작업의 토큰 절감. 설정이 다른 작업 중 흔들리지 않는 구조.
- 결정은 여전히 빠르다("진행해줘"). 결정 대기 항목을 답변 끝에 명시하는 형식이 잘 맞음.

## 교정

- 승격 제안에 릴리즈 컷을 묶은 것 → versioning.md 컷 시점 3가지. 이후 승격 2건은 [Unreleased]에만.
- 시험 E 기록에 "README에 링크"라고 썼으나 실제로는 권한 부족으로 미실행 → 로그로 재확인 후 정정. **세션이 말한 것과 실제 파일 변경을 대조**해야 한다.

## Mac 반영 (저녁 세션)

- "다음 추천" → "지금 확인 가능한지 확인" → "macOS인데 가능?" → "진행해줘". 기기가 바뀌면 **그 기기에서 할 수 있는 항목으로 바로 전환**하기를 원한다. 추천할 때 "어느 기기에서 되는 일인지"를 같이 말하는 게 맞음.
- Windows에서만 시험한 도구(`tools/*.sh`)가 Mac 첫 실행에서 깨짐(`python` vs `python3`). "Windows 통과"는 "공통 통과"가 아니다 — 새 기기 반영이 곧 도구의 2차 시험.
- HANDOFF "다음 할 일" 줄이 완료 항목(C-18·C-13)을 가리키고 있었음. 세션 끝 갱신 때 §0 표뿐 아니라 이 줄도 대조해야 함.
- Mac은 **VS Code만, Xcode 안 씀** → 확장만 신경. Settings Sync가 안 켜져 있어 기본 13개 중 7개 누락이었고, 제외 목록의 `ms-python.vscode-python-envs`·`github.codespaces`는 설치돼 있었음.
- `statusLine`은 터미널 CLI 전용이라 VS Code 패널 사용자에겐 안 보임. 기본 영역이 "터미널 CLI" 전제로 설계된 부분이 드러남 — Mac처럼 패널만 쓰는 기기엔 상태줄이 의미 없음.
- Mac auto memory의 "Homebrew 없음·gh는 `~/.local/bin`"은 낡음(현재 `/opt/homebrew/bin/gh`, 미로그인). 수집본은 스냅샷이므로 월 점검 때 낡은 항목 표시.
- 확장 삭제 제안에 "문제없으면 놔둬" — 기본 목록은 **최소 보장**이지 허용 목록이 아님. 문서(install.md)가 "지운다"로 되어 있어 결정에 맞게 고침. 사용자는 "있어야 할 것"에는 엄격, "더 있는 것"에는 관대.
- C-10은 Windows 육안 확인까지 하고 닫기로 — 검증 항목은 원래 정한 기준을 채워야 닫는다.

## C-45 플러그인화 검토 (밤 세션)

- "다음 진행할 내용 추천" → 기기(Mac)에서 바로 할 수 있는 순서로 추천 → "C-45 진행해줘". 추천은 항목 하나 + 이유 한 줄이면 충분했다.
- 조사는 claude-code-guide 서브에이전트(Sonnet, 약 75k 토큰)로 공식 문서만 읽게 하고, 본 세션은 `--help`·`validate` 실행과 공식 원문 교차 확인만. 조사 규칙(공식 → 실행 검증 → 교차 확인 → 기록) 그대로 돌아감.
- 결론이 "하지 않는다"인 항목도 근거 파일을 남겨야 다음 달 같은 조사를 반복하지 않는다(`docs/research/plugins.md`, 재검토 조건 명시).
- 부산물 둘: Mac에 확장 내장 CLI 바이너리가 있음(HANDOFF의 "Mac CLI 미설치"가 부정확했음), `claude plugin validate`가 스킬 디렉터리 검사에 그냥 쓰임.

## C-25 `/insights` (밤 세션, 이어서)

- "다음 진행해줘" 한 마디로 다음 항목 착수 — 추천 순서를 HANDOFF에 적어 두면 사용자 메시지가 짧아진다.
- `/insights`는 `claude -p`에서도 됨. 3세션 데이터로는 "이미 하고 있는 것"을 지침으로 제안하는 게 대부분 → 월 1회면 충분, 세션 수가 쌓인 뒤가 의미 있음.
- 리포트가 다른 저장소(OpenClaw) 세션의 토큰 노출을 짚음. 이 저장소 몫은 규칙(§7 보강)이고 재발급은 사용자.
