# 관찰 2026-09-08 — claude-config 세션

세션에서 드러난 사용자의 요청·대화 방식. 한 달 뒤([C-21](../../docs/PROGRESS.md#c-21) 점검) 반복되는 것만 `drafts/claude-md/`에 후보로 올린다. 여기는 원자료.

## 요청 방식

- 메시지 하나에 항목 3~7개를 `-`로 나열하고, 각 항목 아래 `>`로 배경·의도를 덧붙인다. `>`가 실제 요구다(예: "리스트화되어 있을까?" → 보드가 필요하다).
- 동사는 세 종류로 구분된다: "확인해줘"(현황 조사), "찾아주고 검토해줘"(커뮤니티·공식 조사 + 우리 상황에 대한 판단), "어떻게 생각해?"(의견과 추천). 셋 다 결론 + 추천 하나를 원하고, 조사 결과는 표로 받는 것을 선호한다.
- "진행해줘"는 직전 답변의 제안 전체에 대한 승인이다. 그 뒤로 중간 확인을 다시 받으면 "다른 저장소에서는 매번 묻지 않던데"라는 피드백이 온다.
- 결정은 빠르다. 추천을 제시하면 대체로 그대로 채택하고, 대신 구조·구분·설명의 명확성에는 엄격하다("작업하는 것과 작업을 위한 것을 나눠라", "'새 세션 인수인계'는 설명이 아니다").

## 원하는 것

- 항목의 **상태 구분**(계획/검증/반영/관리)과 **완료·미완료 구분**을 항상 볼 수 있어야 한다.
- 기본(검증된 것)과 시도(개선 중인 것)가 섞이는 것을 가장 경계한다.
- "무조건 필요한 최소선"이 무엇인지 알고 싶어 한다. 기능 전부가 아니라 효과가 나는 수준.
- 자기 데이터(대화 기록·메모리)로 Claude가 자신을 더 잘 이해하길 원한다. 단 반영은 검토 후.

## 작업 방식

- 세션 하나가 길다(이 세션 12턴, 커밋 9개, 릴리즈 1회). 한 턴에 여러 주제를 병렬로 처리해도 따라온다.
- 문서를 직접 열어 본다(IDE에서 HANDOFF.md를 열었음). 문서의 문장이 곧 사용자 인터페이스다.
